# 内置能力

## 提问与引用

`ask_user` 会等待当前请求的选项或自定义回答。完全访问、自动批准和已记住的授权都不会替用户
作答；回答回到发起请求的会话和工具结果。只有工具明确允许时才显示自定义输入，取消或超时
不生成答案，也不会授予命令或文件操作权限。

输入 `@` 可以选择文件、文件夹、技能、智能体或历史会话。会话引用以标题胶囊显示，完整会话 ID
随草稿保存，重名会话不会互相替换。文件选择保留完整路径，项目外的文件不会被误当成项目内同名文件。
智能体候选来自运行时注册表。历史转录通过 `read` 的 `session://` 地址读取，并标记为参考资料。

消息的技能与会话胶囊来自显式元数据；普通正文和标题不靠关键词删改。技能列表只授权读取已列出的
具体技能文件，不扩大文件写入范围，也不开放整个用户配置目录。

浏览器、索引库、钩子——三样不属于「工具」但决定 agent 能做什么的东西。

## 子智能体

Plume 内置八种子智能体：`general`、`explore`、`review`、`verify`、`plan`、`plan-review`、`simple`、`reason`。
设置 › 智能体在没有会话、刚新建会话或会话尚未载入时也显示这八项，可以提前选择模型和思考等级。
没有单独选择时，八项都跟随主会话的模型。自定义定义里写的模型 id 在本机找得到就用它，找不到就
跟随主会话。保存的覆盖在下一次派发生效。

定义来自同一个 `@plume/core/agents-builtin` 浏览器安全入口，运行时与设置页不维护两份名单。
会话能力加载后使用已合并的项目、用户和内置定义，同名项目／用户定义仍按能力层优先级覆盖内置项。

## 子智能体调度

什么时候派由模型自己判断，依据写在 `task` 工具的描述里：中间产出很大、只要结论的活（翻几十个
文件找一个答案），或者一块与手头工作无关的独立大活。一两步能改完的、正在写的东西的一部分、
要先把接口约定写清楚才能交出去的，自己做。没有设置页，也不随思考等级变化。

同时运行的子智能体最多 4 个，超出的排队而不是被拒绝；配置文件里的 `maxConcurrentSubAgents`
可调，范围 1–8，写盘后下一轮即用新值。只有主对话能派：子智能体拿不到 `task` 工具，不能再派
子智能体，agent 定义里写的 `spawns` 不再生效。见 `runtime/policy/dispatch-guard.ts`、
`runtime/sub-agent/sub-agent-dispatch.ts`。

## 代码审阅：`/review`

`/review` 是一条内建命令，和 `/compact`、`/plan` 列在 `/` 菜单的「命令」组里，命令行也有。正文在
`packages/core/src/commands/review.ts`，敲下去整段展开进发出的那条消息（气泡里只显示 `/review` 和参数），
平时不占请求前缀。桌面端主会话的工具表里常驻一件 `review_session`（工具定义约 680 字符），见下面的
[会话级操作](#会话级操作)。同名的自定义命令盖不住它，和其余内建命令一样。

```
/review [PR 号 | PR URL | 文件路径] [--effort low|medium|high] [--comment]
```

- 不带目标：审未提交的改动，即 `git diff HEAD` 加上未跟踪的文件。没有改动就说明一句后停下，不派子智能体。
- PR：经 `gh pr view` 与 `gh pr diff` 取。`gh` 不存在或没登录时说明原因后停下，不另想办法拼 diff。
  工作区不在 PR 的提交上时只读 diff，不切分支，也不跑检查。
- 文件路径：审整个文件，不是 diff。
- 默认力度：本地改动和文件用 `medium`，PR 用 `high`。

**在桌面端，审阅交给一个新开的审阅会话**（[ADR-0058](../adr/0058-review-in-its-own-session.md)）。写代码的
会话带着「为什么这么写」的全部上下文，自己审容易认同自己，审阅也会占满实现的上下文。所以在主会话里敲
`/review`，它先填一份交接单，然后调 `review_session` 交出去，这一轮就此结束。审 PR 时没有实现可交接，只交目标。

交接单是逐项的必填字段，不是一段自由的总结：审阅会话只知道这里写的，漏一句它就得去猜。

| 字段 | 必填 | 写什么 | 最短 |
| --- | --- | --- | --- |
| `background` | 是 | 为什么做：你最初遇到的问题或提出的需求 | 40 字 |
| `decisions` | 是 | 你在对话里定下的决定和约束，原话加引号；确实没有就明写「用户没有额外约束」 | 8 字 |
| `implementation` | 是 | 实际做了什么、什么方案；和计划不一致的地方为什么偏离 | 40 字 |
| `files` | 是 | 每个改动的文件附一句改了什么 | 每句 4 字 |
| `out_of_scope` | 否 | 故意不做、不该动的，免得被报成漏做 | — |
| `unverified` | 是 | 自己知道没验证、没做完、有疑虑的；确实没有也要明写 | 6 字 |
| `focus` | 否 | 最希望审阅者重点看的地方 | — |

缺项或太短，工具一次列出缺的是哪几项，模型补齐后重发。

- 审阅会话立刻开始，不用再点「开始」：敲 `/review` 就是同意。它开在和原会话**完全相同**的目录里——原会话在
  工作树里就是那棵工作树，否则看不到未提交的改动——在侧栏里挂在原会话下面，名字是「审阅 · 原会话标题」，
  审 PR 或文件时是「审阅 · 目标」。
- 第一条消息照任务说明的写法排：你是审阅会话、只做审阅 → 背景 → 你的决定与原话 → 计划原文 → 实现说明 →
  改动文件 → 不做的事 → 未验证的地方 → 审阅重点 → 目标与力度 → 交付格式。其中两样由运行时从原会话记录里取原文，
  不让模型转述：最后批准的那份计划（连批准时附的注意事项；用过计划模式才有），以及你在原会话里说过的每一句话（从存储里的完整历史取，压缩掉的早期消息也在）
  （按时间顺序；交回的报告、别的会话的消息这类不是你说的不算）。原话总共超过一万二千字时，保留最早一条和最近几条，
  中间注明省略了几条；单条超过三千字先截断。
- 审阅会话对照意图时，以你的原话和决定为最高依据，计划次之；实现说明是作者的自述，要对着代码核实。它派子智能体时
  也把相关的背景和约束写进子智能体的提示词。
- 模型沿用原会话的；设置 › 智能体里给 `review` 选了别的模型、这台机器上又有，就用那个——同一个模型审自己写的
  东西容易得到认同。
- 审阅会话先只审，没有 `--fix` 和 `--comment`。原会话答复修哪几条之前，`write`、`edit` 和 `lsp` 的重命名在它里面
  （连同它派的子智能体）一律被拒；命令不压沙箱，照权限档走，`verify` 跑测试要写缓存。有交接单或计划时多一维**意图对照**：说要做的有没有做、
  做偏、漏做，以及有没有做了计划之外的事。
- 审阅会话写完报告，用 `ask_session` 问原会话修哪几条（原会话的地址写在交接单里）。原会话凭这段对话里你的原话、
  批准的计划和范围来定，定不下来的那几条（多半是 PLAUSIBLE）用 `ask_user` 问你；它答复以后审阅会话才能改文件，
  只修点名的那几条，修完跑相关检查。原会话自己不修。等不到答复（超时、被停下）就什么也不修，报告里列出还在等决定的。
- 原会话里那次调用画成一行「审阅会话 · 标题」，点它切过去看审阅进度。审阅会话做完（它派出去的子智能体都回来、
  问过原会话、修完），报告连同「修了什么、留下了什么、修完的检查」作为一行「来自新会话 · 标题」送回原会话，
  原会话不再修一遍，只向你转述。
  你中途停下审阅会话，报告就不交回；没跑完（出错、到上限）的照样交回，标成没跑完。
- 一次审阅从头到尾在同一个审阅会话里：审、问原会话、修、修完跑检查。再敲一次 `/review` 是一次新的审阅，另开一个审阅会话。

命令行没有 `review_session`，子智能体和侧边聊天也拿不到它；在这些地方 `/review` 照旧在当前会话里跑完整条流水线。

| 力度 | 做什么 | 结论 |
| --- | --- | --- |
| `low` | 审阅的会话自己过一遍，不派子智能体 | 全部标为 PLAUSIBLE，报告注明未复核 |
| `medium` | 并行 3 个 `review` 子智能体，分别看逐行正确性、被删改的行为及其调用方、安全与错误处理与测试覆盖；有意图对照时再加一个，共 4 个；审阅的会话再逐条读代码核实 | CONFIRMED / PLAUSIBLE，推翻的不报 |
| `high` | 再加一个跨文件追踪与对抗视角；之后派一个 `verify` 跑类型检查和相关测试，意图对照也在这一批，每条发现由独立的 `review` 子智能体试着推翻。每批最多 4 个，和子智能体并发上限一致 | 同上，外加检查结果 |

报告按严重程度排序，每条带 `file:line`、一句话的缺陷、具体的触发场景和 CONFIRMED / PLAUSIBLE，
不报风格偏好；没有发现就直说。项目根和改动所在目录的 `AGENTS.md`、`CLAUDE.md`、`REVIEW.md` 会先读，
`REVIEW.md` 写的审阅偏好优先于 `/review` 正文里的默认做法。

`--comment` 只对 PR 有效，由拿着报告的那个会话处理（桌面端是原会话）：发评论是对外动作，发之前先用
`ask_user` 把全文给人确认，只有明确选了「发」才执行 `gh pr comment`。`--fix` 留作兼容：交给审阅会话时修不修
由原会话定，带不带都一样；在当前会话里跑整条流水线时（命令行），照旧要带它才在报告之后修
CONFIRMED 的发现。

## 会话级操作

几件对「这个对话本身」做的事。只有桌面端有：命令行没有，子智能体和侧边聊天
也拿不到——它们不是一个独立的对话。设计见 [ADR-0049](../adr/0049-session-level-operations.md)。

**建议一个新会话（`spawn_session`）。** 做手头这件事时看到另一件值得单独做、但做了会把这次改动
撑大的事——没人用的代码、过期的文档、缺的测试、确认过的 TODO、顺手看到的安全问题——模型不顺手
做掉，也不只在回复里提一句，而是留下一条建议：一个标题、一两句为什么。建议出来时什么都没跑，这一轮
照常往下走。

它和子智能体不是一回事。子智能体是模型自己派、当场就跑、你看不见也插不上话，跑完只把结论交给模型；
建议的新会话要你点了才开始，开出来是侧栏里一个完整的对话，上下文是干净的一份，你能打开、跟它说话、
随时停下，跑完它还在，能接着让它改。

建议画成一张卡片，就在对话里模型提出它的地方，不和前后的工具调用折在一起：标题、一两句为什么、
「开始」。模型还在写这次调用时那里先是一行「建议新会话 · 标题」，写完才换成整张卡片。卡片会被后面的
输出顶上去，所以右上角的环境卡片里「建议的新会话」那一节也列着它、也能开始；环境卡片收着、又有没处理的
建议时，环境按钮上挂一个圆点。

点「开始」才在这个对话的项目里另开一个会话，名字就是建议的标题，背后那段说明作为第一条消息发出去。
「开始」旁边是输入框上那个 ⑂ 开关：项目是 Git 仓库时可以选让新会话在自己的工作树里做，默认跟着
设置 › 工作树。再旁边是「交回这里」：开着的话，新会话做完交给它的那件事（它派出去的子智能体也都回来之后），它最后那段回复会像子智能体的结果
一样送回这个对话——对话里多一行「来自新会话 · 标题」，模型就着它接着做。默认关，模型认为结果会影响
手头的事时才替你打开，你可以在卡片上改；点了「开始」以后，只要它第一轮还没跑完，卡片缩成的那一行后面
也有这个开关，还能打开或关上。只交第一轮，之后你在新会话里接着聊不会再往回送，被你停下的
那一轮也不交。

新会话出现在侧栏里，挂在提建议的那个对话下面，自己在后台跑，你停在原来的对话里不动；对话跑在自己的
工作树里时，新会话开在它所属的项目上，不开进那棵工作树。提建议的对话被置顶或归档时，新会话在侧栏里
单独占一行。下面挂的会话多了，悬停那个对话、点状态点位置上的箭头就能把它们收起来，行尾标出收了几条；
打开的正好是被收起的那条时会自动展开。开始以后卡片缩成一行，说那个会话在做什么——进行中、已完成、没跑完——点它切过去。重开
应用也还是这样：新会话的记录里写着它是从哪条建议开出来的。× 只是在这台机器上把建议收起来，卡片改成
一行「已收起」。

**归档这个对话（`archive_session`）。** 只在你要它归档时用，比如「做完就归档」。它不当场归档——
那会把正在说话的这一轮砍掉——而是让这一轮停在这一下：这一轮收尾之后再归档，会话里没有东西在跑了
再放掉它占着的 MCP 进程和网页。界面离开这个对话。这一轮要是被你停下或出了错，就不归档。
想找回来：设置 › 已归档的聊天。

**交给审阅会话（`review_session`）。** 只在执行 `/review` 时用：主会话写好总结后调它，主进程在同一个目录里
开一个只读的审阅会话、报告交回这里。见上面的[代码审阅](#代码审阅review)。它常驻在主会话的工具表里，不是敲了 `/review`
才加上：中途换工具表会让整段前缀缓存作废（ADR-0044）。所以它的定义压到最短（约 680 字符），每个字段怎么写放在
技能正文第 H 步里，只在用到时才读。

**过一会儿回来接着做（`schedule_wakeup`、`cron_create`）。** 「推上去，十分钟后看 CI」「每 5 分钟看一眼
部署，好了告诉我」——模型可以给这个对话留一个以后的提醒，到点后往这个对话送一条消息，它带着前面说过的
一切接着做。`schedule_wakeup` 是一次性的，60 秒到 24 小时；`cron_create` 用标准 5 字段 cron（分 时 日 月
星期，按本机时区），`recurring: false` 触发一次就删。`cron_list` 列出待触发的（一次性唤醒也在里面），
`cron_delete` 删掉一个。

到点时会话闲着就开一轮；正忙就排到这一轮之后，不插进正在跑的回合。对话里画成一行「定时唤醒 · 理由」，
不是你说的话。上一次触发开的那一轮还没结束时又到点了，这一次跳过，不排成一串，下一次送达会告诉模型跳过了
几次。循环任务 3 天后过期，过期前最后一次送达会说这是最后一次；每个对话最多 10 个。

它们只活在这次运行的内存里：退出应用就没了；你按停止、或者对话被归档、删除时，全部一起取消——自动续跑是
模型的决定，按停止就是收回它，取消了会弹一句「已停止，N 个定时唤醒一并取消」；退出应用时不写这句，你没有按停止。
正在跑时「现在就发」、编辑重发也会先停下这一轮，但不取消它们：对话还在往下走，模型还等着它们。那时已经到点、
排在这一轮之后还没轮上的那一次会随这一轮一起清掉，一分钟后补送一次。撤回或编辑重发截掉的那一段里建的唤醒
跟着取消：说「十分钟后再看」的那句话已经不在对话里了。右上角环境卡片里「定时唤醒」那一节列着还没触发的：说的是什么、什么时候、循环还是
一次、何时过期，每项都能取消；卡片收着时环境按钮上挂一个圆点。

这和「定时任务」页面不是一回事：定时任务每次开一个**新**会话、存在设置里、重启也还在。要「以后每天早上都
跑一遍」这种，模型会请你去定时任务页建，不用这几件工具。子智能体、侧边聊天和命令行都没有它们。

## 计划模式

`/plan` 切换，或点输入框旁的开关。开着时模型只能读、搜、列、问，会改东西的调用（`edit`、`write`、
非只读的 `bash`、`lsp` 的 rename、标了会改的 MCP 工具）直接被拒绝，并被告知去调 `submit_plan`。
只读的 `bash` 命令在只读沙箱里跑。工具表不变，所以前缀缓存不断。

模型调 `submit_plan` 时会弹一张审批卡片，右栏同时打开「计划」面板：一段 Markdown，通常是标题、概要、主要改动、测试和假设。
在面板里选中一段字可以留评论，那段字画下划线、挂一个序号，评论按同样的序号列在审批卡上。「接受」后同一轮里
所有工具恢复，模型按计划动手、自己拆任务清单，有评论时评论作为「执行时注意」一起交给模型，计划不重写；「修订」把评论和补充的话
作为反馈发回，模型改完重交；「拒绝」这一轮就结束。完全访问和「总是允许」都不会替你批准计划。批准的计划（连同
注意事项）在压缩后仍会原样注入，同时写成一个文件，放在会话临时目录的 `plans/` 下，之后不再改动。
它和权限档互不影响。派出去的子代理受同一个开关管。见 ADR-0044。

想把讨论和实施分开，就点「在新会话里执行」：计划照样批准、写成文件，这个会话停在这里，Plume 在同一个项目里
开一个新会话去实施，挂在这个会话下面。新会话的第一条消息只有标题、概要、计划文件路径、授权范围（按计划改代码
和验证，提交、推送这类计划没写到的事先问人），以及有疑问时该问谁：能从代码查到的自己查，计划没定下的意图和
取舍用 `ask_session` 回来问这个会话。新会话默认用设置里的默认模型；按钮旁那枚箭头可以给它另挑一个，挑了
以后按钮写成「用 某模型 在新会话里执行」，这个会话自己的模型不变。

从这个会话交出去的会话——交给新会话的计划、建议的新会话、审阅会话——在输入框上方各占一行：跑着时说它此刻在做
的那一步（「读取文件 README.md」「执行命令 …」），在等人、跑完、没跑完也写在那里，点一下切过去。转录往上翻它也
不动；跑完的那一行留到你点进去看过为止。讨论计划时想先让人挑一遍毛病，可以派只读的 `plan-review` 子智能体，
它只看计划正文，交回是否通过和每条阻塞项的证据与最小修正。

## 浏览器

`web_fetch` 拿到的是服务器发来的 HTML。桌面浏览器使用真实的 `<webview>`，Agent 的
`browser_*` 工具直接控制面板中可见的同一组标签，读取脚本执行后的页面，并通过原生输入点击、输入。
标签按会话隔离：每个会话看到的是自己开的那些页面，切走再切回来还是原来那一张。页面本身按最近
三个会话保留——每张页面都是一个渲染进程，更早的会话切回时重新加载，正在跑 turn 的会话不受这条
影响。销毁会话时回收对应标签。

地址栏也是搜索框：不像网址的东西直接交给搜索引擎，输入时下拉会先告诉你它打算搜还是打算打开，
并列出匹配的书签。搜索引擎在「设置 → 浏览器」里选，默认必应，也可以填自定义地址（用 `%s`
代表搜索词）。地址栏旁的「⋯」菜单集中提供新建／关闭标签、书签、检查元素、框选区域、开发者
工具、缩放与视口尺寸。只有多个标签时才显示标签行。

Agent 光标由面板覆盖层绘制，采用圆润的黑色箭头、白色描边和蓝色光晕，兼顾浅色与深色网页。
点击时显示蓝色圆环，系统开启减少动态效果时停用移动和圆环动画。坐标按网页缩放与视口适配比例换算，
光标本身保持固定显示尺寸。网页的弹窗、样式和导航不会遮住或销毁它；滚动显示视口中心的操作位置，
键盘操作保留最后位置。读取与任意 `eval` 不会虚构鼠标移动。`browser_screenshot` 截取网页内容，
不包含面板绘制的光标装饰；检查光标本身需截取真实应用窗口。

**边界**：页面内容是不可信输入。它被包在一个明说「这是不可信的」的标签里交给模型，绝不当作指令
执行。超时是硬的——15 秒不回应的求值和 30 秒不加载完的页面都会被放弃，读回的文本上限 40000 字。

面板里的 `<webview>` 另有三道守卫（剥掉 preload、禁 node、限制能加载的协议），见
[ARCHITECTURE.md](../../ARCHITECTURE.md) 的「边界」。

## 索引库

`grep` 回答「这段文字出现在哪」，索引库回答「这个东西在哪定义的」。

在大仓库上这个差别很要紧：grep 一个 `applyDiscount` 会返回每一处调用，索引返回的是定义它的那
一行。

定义是用正则识别的，不是解析出来的。每种语言配一个真正的解析器会更准，但也要为每种语言引一条
工具链；一个认得各语言声明形式的正则，足以把 agent 带到正确的文件和行号——那是它在开始读之前
需要的全部。

在设置 › 索引里建立和重建。

## 钩子

钩子是在特定事件发生时自动运行的命令，协议与 Claude Code / ZCode 的 hooks 一致。在设置 › 钩子
里管理，分两个范围：

- **用户**：存在设置文件的 `hooks` 里，对所有项目生效。
- **项目**：存在项目的 `.plume/config.json` 的 `hooks` 里，只对这个项目生效。项目钩子可能是别人
  提交进来的，所以**信任之前不会运行**：会话里跑到它只记一笔「已阻止」，输入框上方提示待审核，
  在设置页逐条点「信任」。信任按内容指纹记在 `~/.plume/hook-trust.json`，改过的钩子要重新信任；
  在设置页里亲手新建或修改的项目钩子自动信任。

九个事件：`SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PermissionRequest`、`PostToolUse`、
`PostToolUseFailure`、`Stop`、`StopFailure`、`SessionEnd`。

- `SessionStart` 在会话第一次发消息时跑，不是打开会话时。
- `StopFailure` 在一轮没有正常收尾时跑（正常收尾走 `Stop`），输入带 `reason`：`error`、`aborted`
  （按了停止）、`max_turns`、`stalled`，出错时另有 `error`。匹配器匹配的就是 `reason`。
- `SessionEnd` 在跑过 `SessionStart` 的会话被释放时跑，`reason` 是 `deleted`、`archived`、`moved`、
  `evicted`（同时开着的会话太多，最久没用的那个被收起，再发消息会重新触发 `SessionStart`）、
  `quit`（退出应用，最多等 2 秒）或 `exit`（命令行跑完）。
- 这两个事件只观察，输出和退出码都不影响任何东西。

```json
{
  "hooks": {
    "events": {
      "PreToolUse": [
        { "matcher": "Bash|Write", "hooks": [{ "type": "command", "command": "./scripts/guard.sh", "timeout": 30 }] }
      ]
    }
  }
}
```

- **运行方式**：`command` 交给 shell 执行（可指定 `shell`，`async: true` 后台运行、不等结果）；
  `process` 直接起进程，`args` 是 argv 数组，超时用 `timeoutMs`。默认超时 60 秒。
- **匹配器**：留空或 `*` 匹配全部；只含字母数字、`_` 和 `|` 时按名字精确匹配（工具名同时认
  `bash` / `Bash` 两种写法）；其余按正则。`Bash` 也匹配 `monitor`：它跑的同样是一条 shell 命令，
  `tool_input.command` 和 `bash` 同形，`tool_name` 是 `monitor`。
- **输入**：事件的 JSON 从标准输入送进去（字段同时给 camelCase 和 snake_case，如 `tool_name`、
  `tool_input`）；环境变量有 `CLAUDE_PROJECT_DIR`、`PLUME_PROJECT_DIR`、`CLAUDE_SESSION_ID` 等。
- **输出**：退出码 0 时读标准输出里的 JSON（`decision`、`reason`、`additionalContext`、
  `hookSpecificOutput.permissionDecision` 等，不是 JSON 就忽略）；退出码 2 表示阻止，原因取
  标准错误；其他退出码记为失败但不阻止。多个钩子的权限结论取最严的一个（deny > ask > allow）。
- **提权例外**：命令要求到沙箱外运行（提权）时，钩子的 allow 不算数，仍由人在提权卡片上批准；
  钩子的 deny 照常生效。
- `Stop` 钩子要求继续并给出原因时，这一轮会接着跑，最多连续三次。

每一轮跑过哪些钩子、结果如何，在回复下方的操作栏里点钩子图标查看。子智能体里的工具调用同样经过
`PreToolUse` / `PostToolUse` 等钩子，输入里多两个字段（主对话里没有）：`agentName`（`agent_type`）是
子智能体的名字，比如 `general`；`agentId`（`agent_id`）是这一个子智能体自己的 id，同一种并行派了
几个时靠它区分。字段名与 Claude Code 一致。它们的运行记录在子智能体自己的面板里：每一段（派出去的
那一次、每次续跑）收尾处有一个钩子图标，主对话的图标里不列它们。

和 Claude Code 还差的：内置子智能体的 `agent_type` 用的是 Plume 的名字（`explore`、`general`），
不是 Claude Code 的 `Explore`、`general-purpose`；子智能体也不触发 `Stop`。**待做**：
`SubagentStart` / `SubagentStop` 两个事件——派出一个子智能体、它跑完时各触发一次，现在还没有。

## 从别的应用打开会话

macOS 上，别的应用可以用一个 URL 让 Plume 切到指定会话：

```
plume://open-session?id=<会话 id>
```

会话 id 就是钩子输入里的 `session_id`。Plume 没在运行时会先启动，等窗口加载好再打开。id 对不上
任何会话时提示「会话已不存在」，留在原来的会话；不是这个形状的 URL 不做任何事。它和点击任务完成
通知、托盘里的最近会话走的是同一条路径。

只有正式安装的包会收到这种 URL：scheme 是打包时写进应用的，从源码运行的开发版没有向系统声明它。
